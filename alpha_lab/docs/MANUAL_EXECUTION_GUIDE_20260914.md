# 邮件播报—人工执行

用户已明确采用邮件播报、人工下单。券商CSV自动适配和完整罕见公司行动自动处理不再是该模式的启动前提；此前自动执行入口的全局阻断规则保留供其自身审计，不沿用于人工模式。

## 日常流程

1. 用已核对的现金、持仓生成收盘计划，保留五股、整手、限价和不预支未到账卖款的约束。
2. 邮件给出股票、买卖方向、股数、限价、原因及异常提示。无交易计划时明确写“无新增买卖计划”。
3. 下单前只对拟交易股票，在客户端确认ST/停牌、价格范围、可用资金/可卖量和明显公司行动。
4. 手动执行后反馈实际成交或未执行。部分成交按实际数量记录；确认、播报和建议均不算成交。
5. 用收盘持仓和现金核对账本，下一份计划以实际结果为准。

不要求用户编写JSON或适配券商CSV；可根据人工反馈整理机器记录。实际费用未知时，先保留待核对信息，不假定为0后宣称账户已对平。

## 公司行动按股票处理

已知除权或其他异常的股票暂缓；其他股票分别核对，不因自动事件全集不完整而暂停整个账户。遇到配股、换股、股数异常等少数事件，保留凭据后人工处理该股票。事件造成账户总现金或股数对不上时，仍须核清后再依赖该账户预算。

本轮没有统计或证明这些事件的发生频率；调整依据是用户选择的人工操作模式。自动日状态接口缺项可以由实际客户端核对补充，但不能把缺数据写成“没有风险”。完整收盘行情、交易日期和真实持仓仍然必需。

## 工具

`scripts/manual_execution.py` 提供：

- `prepare --db ... --bundle ... --calendar ... --output plan.json`：冻结人工准备计划；不要求券商适配或公司行动全集通过。
- `draft --plan ... --metadata ... --output 新目录`：生成中文 `briefing.txt` 和 `briefing.eml`。可交给[持久化发件箱](MAIL_OUTBOX_20260914.md)处理；尚未实际发送，收件范围待确定。
- `review --db ... --input ...`：逐单记录人工核对；一单失败不影响另一单核对。
- `skip --db ... --input ...`：记录未提交及原因，不改变现金/持仓。内部复用终结状态并额外标记 `manual_not_submitted`，审计事件明确为人工未提交，不伪造券商拒单。
- `fill / terminal / snapshot`：沿用实际成交、实际撤单和收盘对账接口。

核对记录包括账户、股票、核对时刻、客户端状态和凭据。存在部分成交时不能用“未提交”抹去，必须记录成交及剩余部分的真实终态。

当前策略仍按次日开盘窗口验证，人工模式不会自动把它变成任意盘中价格成交。过期邮件标记“历史核对，勿执行”；准备入口拒绝过期、未来才获取或明确标记回补的输入。现有9月11日观察包不能成为当前下单依据。

## 本轮验证

新增7项人工流程测试，与此前56项一起运行，共63项通过。验证邮件生成不改变账本、一股公司行动异常不阻断另一股、未执行和部分成交后撤单、重复反馈去重、收盘核对，以及过期/未来/盘前收盘回执拒绝。

策略收益未重测，人工执行偏差也未认证。当前剩余重点是：有效的每日数据、实际账户起点、发信接入，以及后续交易日人工回报核对。无需先完成券商自动适配和所有罕见事件自动化。
