# alpha_lab 文件索引与存储规则

日常从 [工作台](../INDEX.html) 或 [文字入口](../INDEX.md) 开始。研究文件保持原路径，统一通过索引寻找；当前策略以配置及最新正式扫描为准，历史文档中的收益和结论需要复现。

## 找文件

| 要找什么 | 入口 |
|---|---|
| 当前规则、最新正式候选、行情核验 | 工作台顶部的当前工作卡片 |
| 养殖、酒店、板块模型、个股筛选等研究 | 网页搜索中文关键词，按主题筛选 |
| 某个实验的所有版本 | 类型选“运行 / 产物”，搜索实验名 |
| 哪些目录文件最多、占空间最大 | 类型选“产物族”，按文件数或空间排序 |
| 固定文本目录 | [文档索引](INDEX.md)、[产物索引](../outputs/INDEX.md) |
| 具体大文件和静态引用情况 | [存储清单](../catalog/STORAGE.md) |

网页可直接打开，搜索数据内嵌，不需要服务器或联网。命令行搜索使用小型SQLite目录库，不遍历80万个原始文件。只索引文档、运行目录和产物族，原始明细仍在各自运行目录内。

```bash
# 元数据刷新：日更模型完成后执行；复用上次容量盘点
python alpha_lab/scripts/build_workspace_index.py build

# 查询标题、路径、文档章节，多个词同时匹配
python alpha_lab/scripts/build_workspace_index.py search "养殖"
python alpha_lab/scripts/build_workspace_index.py search "sector_live" --kind run

# 完整盘点：新增大量产物或准备归档时执行
python alpha_lab/scripts/build_workspace_index.py build --inventory

# 已找到目标运行后，再搜索具体文件
rg --files alpha_lab/outputs/<实验名>/<运行编号>
```

当前日更程序保持原样，没有添加定时任务或修改数据构建流程。索引刷新需要执行上述命令；网页会显示元数据时间与容量盘点时间。新增目录未做完整盘点时显示“未盘点”，不是零占用。

## 当前与历史的边界

1. 最新日报/模型入口读取已存在的 `LATEST`、`LATEST_CANDIDATES`、`LATEST_SCAN`、`LATEST_UPDATE`，并检查目标存在且清单声明完成；不按修改时间选最新。
2. `LATEST_POLICY_REVIEW` 单独标为历史规则复核，不能替代正式新信号。
3. 索引读取清单声明，不代替哈希审计或收益复现。没有清单、没有数据日期的记录保留“未声明”，不伪造为成功。
4. `docs/current_strategy_20261013/` 包含历史版本与后续变更，不是文件夹中每份文档都代表现行规则。当前入口显式链接策略配置与暂停年度板块判断的说明。
5. `configs/workspace_index.json` 仅管理导航、主题分类和当前依赖保留名单，不修改策略参数。新增主题或固定入口在这里登记。

## 新文件怎样存

既有目录不搬迁。后续新增研究建议遵循：

```text
docs/<主题>/
  README.md                  # 问题、当前结论状态、证据与运行链接
  DESIGN.md                  # 稳定方法/时序约束
outputs/<实验名>/<运行编号>/
  manifest.json              # 状态、asof、来源、参数/权重/产物哈希
  summary.json               # 少量可读结果；声明数据日期与记录性质
  REPORT.md / REPORT.html    # 本次结果、限制、复现命令
  config.yaml                # 本次配置副本
  sources/                   # 必要源码快照
  tables/                    # 统计表、诊断明细
  figures/                   # 图与导出文件
  logs/                      # 运行日志
  trials.parquet             # 大批试验记录尽量合并存储
```

`docs` 保存稳定说明和证据链接；重复的CSV、图片、PDF导出放在运行产物中，不在多个文档目录复制整套。已纳入旧清单的文件仍保持原样；此规则适用于新工作，不追溯修改旧快照。

未来新实验的数十万试验，优先按“阶段/年份/折”保存少量Parquet表，使用 `trial_id`、`seed`、`fold` 等列标识，模型权重只保留复现所需版本。每次试验一个JSON、一个小Parquet、一个独立文件夹会造成目录和inode膨胀。更换存储结构须在新实验版本中实现，不直接替换旧运行内部格式。

## 分层保留与归档

| 层级 | 内容 | 方法 |
|---|---|---|
| 当前工作 | 最新扫描、核验、实际依赖的权重/源码/事件来源 | 原路径在线保留，保留完整证据 |
| 研究归档 | 已结束但需要复现的实验 | 保留报告、清单、配置、源码、核心模型及必要明细；按实验/运行查找 |
| 冷存储候选 | 大型旧试验明细、重复中间导出 | 完成依赖核验后按运行打包，并保存包内清单与SHA-256；核验可恢复后再决定是否移走原件 |

当前链路显式保留 `sector_asof_replay_v1`、`stock_selection_asof_v2`、形态事件来源及日更记录等。源码还会直接从某些旧输出目录导入模块，因此“旧日期”不等于“不再使用”。存储清单的静态引用统计只是线索，未命中也不能据此删除。

归档前依次核对：静态/动态依赖、快照清单、复现所需数据、归档包完整性与抽样恢复。容量统计区分逻辑大小和实际分配空间；减少文件数与节约字节不是同一个目标。压缩前需要临时空间，当前目录不会自动执行打包或删除。

本轮实施了导航和检索层，没有移动、删除、压缩原研究文件，没有释放原有产物占用。索引可由同一命令重建；生成页、JSON和SQLite都不是原始证据。
