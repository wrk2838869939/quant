# 固定数据、固定模拟口径、只迭代策略

目标：支持日频至月频的选股研究，在小资金账户约束下评价收益与风险。
数据和查询接口固定为独立版本，策略实验无需反复下载、修复或重建历史数据。

## 已落地的数据边界

- 初始版本：`releases/selection_v1_20260920`。包含现有 A股、美股、指数、主档、日历、查询源码、审计配置和已知限制说明。
- 所有内容独立复制，不使用硬链接；活动目录的更新不会改变旧版本。
- `snapshot_manifest.json` 记录每个输入文件的 SHA256、整体内容标识及 Python/pandas/numpy/pyarrow/joblib/PyYAML 版本。
- 实验启动前校验快照；数据、查询代码或依赖变化时明确失败，避免把不同输入的结果当成策略提升。
- 缓存和实验输出不参与冻结；策略输出写在 `alpha_lab/outputs/`，策略源码放在 `alpha_lab/`。
- 冻结是版本隔离和校验机制，不是操作系统写保护，也不是数据质量认证；不代表已有模拟引擎完成与该快照的适配。

## 使用

项目根目录下运行：

```bash
# 首次创建；同名版本禁止覆盖
python datahub/scripts/frozen_research.py freeze \
  --release datahub/releases/selection_v1_20260920

# 校验输入与计算环境
python datahub/scripts/frozen_research.py verify \
  --release datahub/releases/selection_v1_20260920

# 用固定的查询包和固定数据运行自己的策略入口
python datahub/scripts/frozen_research.py run \
  --release datahub/releases/selection_v1_20260920 \
  alpha_lab/scripts/your_strategy.py --your-argument value
```

最后一条中的策略脚本是占位示例，替换为实际文件。脚本内部直接使用：

```python
import os
from datahub import DataHub

hub = DataHub()  # 启动器已绑定冻结包及 DATAHUB_ROOT
input_identity = {
    "snapshot_id": os.environ["DATAHUB_SNAPSHOT_ID"],
    "content_id": os.environ["DATAHUB_CONTENT_ID"],
}
prices = hub.cn.daily("000001.SZ", "2020-01-01", "2020-12-31",
                      fields=["open", "close", "hfq_close", "vol_share", "amount_yuan"])
```

只传 `DataHub(root=...)` 可以固定数据路径，但未必固定正在 import 的计算代码；推荐使用启动器。
启动器不会隔离策略的任意文件或网络访问。策略必须遵守契约，不显式另建活动数据根、不导入其他数据包绕过固定输入。
已有 alpha_lab 脚本若直接读旧路径，不会自动改用快照，需要在数据适配层一次性接入。

## 三层职责

| 层 | 职责 | 同一轮策略对比是否允许改变 |
|---|---|---|
| 数据层 | 价格、量额、复权、元数据、日历、固定口径基础指标 | 不允许；修复或扩充发布新版本 |
| 模拟层 | 可交易股票池规则、成交时点、现金/股数、费用、滑点、公司行动、报告 | 不允许；升级后重跑共同基线 |
| 策略层 | 因子、评分、选股数量、买卖触发、日频至月频调仓、仓位建议 | 允许；模拟层仍须执行固定账户约束 |

“只修改策略模块”应同时固定模拟层。否则改手续费、成交价或停牌处理，也会制造不可比较的收益变化。
项目已有 `alpha_lab/src/portfolio.py` 等现金/股数账本，后续应选定并验证一个接口再固定；不再为每个策略复制一份回测引擎。
当前 `causal_portfolio.py` 自身限制为主板/月度/最多5只等特定契约，不应未经适配宣称支持所有日频策略。

## 模拟账户与待接入项

用户已确认：日频至月频选股研究，**初始资金 100,000 元，最大可接受回撤 30%**。
独立配置为 `alpha_lab/configs/selection_account_v1.yaml`（相对于项目根目录）。
回撤按含初始资金的历史账户净资产峰值到低点计算，包含现金、持仓市值及交易费用；30% 是结果验收上限，不是单股止损比例或保证成交的强平线。
例如净资产峰值为 12 万元时，回落至 8.4 万元即为 30% 回撤，不能始终按初始资金固定亏损 3 万元理解。
既有引擎的负数 `mdd` 口径对应验收条件 `mdd >= -0.30`；缺失或非有限指标不能视为通过。
账户配置绑定冻结数据的内容标识，已由经典策略工程测试入口接入；其他既有实验或实盘入口不会自动改变。
允许市场、持仓上限、杠杆/做空约束、费用与成交模型仍需在模拟层统一固定。
跳空和无法成交意味着实际回撤可能超过阈值，不能通过截断净值来制造满足风险限制的结果。

此处为用户后续确认的账户约定。冻结快照中的文档保留冻结当时的状态，不为更新账户参数修改旧快照。

拟采用的日线时序边界：截至 t 日已可得信息生成信号，最早下一可交易时点执行；精确成交模型在模拟层固定。
个股基础指标按已记录行情计算，不能把观测行位移直接等同于市场交易日位移。
新的自定义因子属于策略层，可从冻结的基础行情派生；不必为了增加因子重建数据集。

## 让数据问题不再反复打断实验

1. 每个研究版本先固定市场范围和依赖字段；与该策略无关的美股日历、行业映射问题不阻止纯沪深价量研究。
2. 缺失字段或不合格历史身份按固定的、事前声明的规则处理，记录覆盖损失；不能根据后续涨跌选择排除股票。
3. 所需停复牌、官方价格限制和公司行动资料应在模拟接入时批量准备并校验一次。当前 datahub 尚未包含这些完整执行输入；不能只冻结日线后假设账户模拟已完整。
4. 单个实验不联网补数据，不临时改行情，不临时改变缺失值策略。常规回测只校验版本和实际使用字段，不重跑全项目数据调查。
5. 遇到真实重大数据错误，发布 v2，保留 v1 结果；在新版本上重跑基线与候选，禁止跨版本直接比较优劣。
6. 历史窗口已经参与过多轮研究，不能因新建目录或快照就重新称为未使用的 TEST；实验记录须标明研究使用历史。

每次实验最低记录：数据内容标识、策略代码版本、模拟代码版本、配置、日期范围、随机种子、持仓/交易账本、覆盖与拒单原因。
主要评价是费用后的组合结果和风险表现；“精准选股”需要样本外验证，不由接口正确或单个高收益回测自动证明。
