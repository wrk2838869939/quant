# 算子一致性修复记录（2026-09-11）

## 范围与证据

本轮仅使用合成面板验证表达式引擎；未读取或扫描 TRAIN/VALID/TEST 行情，未重新挖掘或修改历史因子产物。
修复前 6 个 unittest 方法产生 161 项失败子检查和 76 项错误；修复后通过。
这些数量包含设备、精度、算子和窗口组合，不代表独立缺陷数。

## 统一后的契约

- 滚动均值、和、标准差及极值允许起始部分窗口，满足 `max(2, d // 2)` 个非缺失值即输出；输入短于窗口仍返回原形状。
- 时序及截面标准差统一为样本标准差（`ddof=1`）。原 CPU Bottleneck 注册路径使用默认 `ddof=0`，此处改变其历史数值。
- `tsrank` 使用 Bottleneck 平均秩定义，范围 [-1, 1]；当前值缺失则返回 NaN。
- `decay` 保留 CPU 既有定义：完整窗口内任何 NaN 均传播；不将缺失值填零，也不按有效权重重归一。
- `corr/cov` 使用成对有效样本，门槛为 `max(3, int(d * 0.7))`；常量序列相关系数为 NaN；`cov` 真正计算样本协方差。
- `argmax/argmin` 返回极值距当前日的位置，并列时取最近者；GPU 注册表补齐这两个算子。
- `sign` 保留 NaN；安全除法将无穷结果改为 NaN；移位及差分支持短历史。

## 复现

在仓库根目录执行：

```bash
python -m unittest discover -s alpha_lab/tests -p 'test_operator_parity.py'
```

覆盖全部 28 个注册算子、5/10/20/60 日窗口、缺失值、常量、并列值、短历史、嵌套表达式和 CPU 排名/极值位置的无 Bottleneck 回退。
Torch CPU 始终执行；有 CUDA 时同时执行 GPU；两条路径均检查 float32/float64。另检查时序算子的输出不随未来输入变化。
验证环境：PyTorch 2.1.2+cu118，Bottleneck 1.6.0，CUDA 可用。

## 使用限制与后续

本轮证明上述合成用例的计算一致性，不证明因子收益、IC 或统计有效性，也未做全市场性能测试或所有数值尺度的压力测试。
历史 GPU 产物可能受到多项语义差异影响，不能因本轮测试通过而恢复认可；保留旧产物作为审计证据。
后续应先在 TRAIN+VALID 重算候选因子，再核对 GPU/CPU 的 IC 评估路径（包括标签缺失时的成对样本与排名处理）。
TEST 窗继续冻结；前向跟踪需使用修复后的固定定义重新生成因子。
